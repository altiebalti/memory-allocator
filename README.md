# Memory Allocator

**Лабораторна робота №2** · Тимченко Олександр, група ТК-41

Реалізація власного алокатора пам'яті мовою C — рішення завдання
[Memory Allocator](https://github.com/open-education-hub/operating-systems/tree/main/content/assignments/memory-allocator)
(OpenEduHub · Operating Systems). Повний текст завдання — у [`ASSIGNMENT.md`](ASSIGNMENT.md).

Реалізовано чотири функції у [`src/osmem.c`](src/osmem.c):

| Функція | Призначення |
|---|---|
| `os_malloc(size)`  | виділення `size` байтів неініціалізованої пам'яті |
| `os_calloc(n, sz)` | виділення масиву `n × sz`, обнулене |
| `os_realloc(ptr, size)` | зміна розміру блока |
| `os_free(ptr)` | звільнення пам'яті |

Усе будується поверх системних викликів Linux `brk()`/`sbrk()`, `mmap()` і
`munmap()`.

---

## Коротко про реалізацію

* **Метадані блока** — `struct block_meta` (32 байти на 64-бітній системі):
  розмір, статус (`FREE`/`ALLOC`/`MAPPED`), покажчики `prev`/`next`.
  Функції повертають адресу *payload*, тобто `block + 32`.
* **Вирівнювання** — усе (і метадані, і payload) вирівняне до **8 байтів**.
* **brk vs mmap** — якщо `вирівняний_розмір + метадані < 128 КБ` (`MMAP_THRESHOLD`),
  блок береться з купи (`brk`); інакше — через `mmap`. Для `calloc` поріг —
  розмір сторінки (`getpagesize()`, 4 КБ).
* **Попереднє виділення (preallocation)** — при першому зверненні до купи
  одноразово запитується цілих **128 КБ**, з яких далі «нарізаються» блоки.
  Це різко зменшує кількість викликів `brk()`.
* **Повторне використання + best-fit** — звільнені блоки купи лишаються у
  списку й перевикористовуються: обирається **найменший вільний блок, що
  підходить**.
* **Split** — завеликий вільний блок ділиться; залишок стає новим вільним
  блоком (лише якщо в залишок вміщається метадані + щонайменше 8 байтів payload).
* **Coalesce** — сусідні вільні блоки зливаються (ліниво: перед пошуком блока та
  під час розширення в `realloc`).
* **Розширення останнього блока** — якщо потрібного вільного блока немає, але
  останній блок купи вільний, він розширюється через `sbrk` замість створення
  нового.
* **`realloc`** — намагається змінити розмір *на місці* (звуження зі split;
  розширення останнього блока через `sbrk`; поглинання наступних вільних
  сусідів); копіює дані в новий блок лише коли на місці не виходить. Перехід
  heap↔mmap обробляється переміщенням.
* Кожен системний виклик перевіряється макросом `DIE()`.

## Збірка

```sh
make -C src            # збирає libosmem.so
make -C tests snippets # збирає тест-програми
```

## Запуск офіційних тестів

> ⚠️ **Важливо.** Офіційний грейдер (`tests/run_tests.py`) знімає трасу кожної
> тест-програми через **`ltrace`** і порівнює її з еталонами в `tests/ref/`.
> Перехоплення бібліотечних викликів у `ltrace` працює **лише на x86_64**.
> На Apple Silicon / `aarch64` `ltrace` бачить системні виклики, але не бачить
> `os_malloc`/`os_free`, тому грейдер там не запускається. Потрібен **x86_64
> Linux**.

На x86_64 Linux:

```sh
cd tests
make check          # повна перевірка: ltrace-діф + перевірка витоків valgrind
# або
python3 run_tests.py
```

Очікуваний результат — **усі 40 тестів пройдено**:

```
...
test-all                         ........................ passed ...   5

Total:                                                         90/100
```

> Сума балів 40 тестів = **90**, тож при повному проходженні грейдер показує
> `Total: 90/100` — це максимум автоматичної частини (решта 10 балів — поза
> автотестами). «Passed» у кожному рядку означає, що траса збіглася з еталоном.

## Перевірка на машині без x86_64 (Apple Silicon тощо)

Щоб переконатися у коректності без `ltrace`, у репозиторії є незалежна від
архітектури перевірка — [`verify/`](verify/README.md). Вона лінкує кожну
тест-програму з `osmem.c` та з хуками `--wrap` на `os_*` і `sbrk`/`mmap`/`munmap`,
відтворює ту саму нормалізовану трасу (адреси відносно початку купи) і порівнює
її з `tests/ref/`. Результат ідентичний на x86_64 і aarch64.

```sh
bash verify/run_verify.sh
# behavioural match vs reference traces: PASS=40 FAIL=0
```

Її зручно запускати у Docker (підходить і для ARM Mac):

```sh
docker build -t memalloc verify            # образ з gcc+python3
docker run --rm -v "$PWD":/work -w /work memalloc bash verify/run_verify.sh
```
